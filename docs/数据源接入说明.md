# 数据源接入说明（请求方法 · 鉴权 · 资产）

> 面向：排查 401/403/429、想换数据源、或自己接新 provider 的人。
> 代码：`clients/stac.py`（检索）· `ingest/signing.py`（SAS）· `auth.py`（OAuth2/M2M）·
> `ingest/fetcher.py`（资产获取）· `ingest/rangefile.py`（按需读）· `configs/providers.yaml`（配置）
>
> 本文所有请求/响应片段均为 2026-10 实测抓取，不是推测。

## 1. 总览

| provider | 类型 | 检索端点 | 检索鉴权 | 资产 URL | fetch_mode | 默认 |
|---|---|---|---|---|---|---|
| `earth-search` | STAC | `https://earth-search.aws.element84.com/v1` | 无 | `sentinel-cogs.s3.us-west-2.amazonaws.com/...` | vsi | ✅ |
| `planetary-computer` | STAC | `https://planetarycomputer.microsoft.com/api/stac/v1` | 无 | `landsateuwest.blob.core.windows.net/...`（需 SAS） | vsi | ✅ |
| `usgs-landsat` | STAC | `https://landsatlook.usgs.gov/stac-server` | 无 | `landsatlook.usgs.gov/data/...`（下载需账号） | download | ✅ |
| `cdse-s2` | STAC | `https://catalogue.dataspace.copernicus.eu/stac` | **检索公开** | `s3://eodata/...`（下载需 OAuth2 + S3 凭证） | download | ✅ |
| `usgs-m2m` | M2M JSON API | `https://m2m.cr.usgs.gov/api/json/stable/` | M2M token | 同上 | download | ❌ |
| `cdse-odata` | OData | `https://catalogue.dataspace.copernicus.eu/odata/v1` | OAuth2 | 同上 | download | ❌ |

前四个共用 `StacClient`（pystac-client），差异只在 URL / collections / 鉴权头 / 资产获取。

## 2. 统一检索：`POST {stac_url}/search`

### 2.1 真实请求

```bash
curl -s -X POST https://earth-search.aws.element84.com/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"collections":["sentinel-2-l2a"],
       "bbox":[112.5,37.7,112.6,37.8],
       "datetime":"2026-09-01T00:00:00Z/2026-10-30T00:00:00Z",
       "limit":50,
       "query":{"eo:cloud_cover":{"lte":30}}}'
```

### 2.2 参数（`stac.py:157` 组装）

| 字段 | 何时带 | 说明 |
|---|---|---|
| `collections` | 总是 | 来自 `providers.yaml`，一个 provider 可配多个 |
| `ids` | 按 id 反查 | 与 bbox 互斥，优先级最高（下载/详情用） |
| `bbox` / `intersects` | 有 AOI | 二选一；多边形走 `intersects` |
| `datetime` | 有日期 | `YYYY-MM-DDTHH:MM:SSZ/...`；缺省 `1970→now` |
| `query` | 云量上限 | `{"eo:cloud_cover":{"lte":N}}`，**服务端过滤** |
| `max_items` | 总是 | 上限 50 |
| `limit` | 总是 | **= max_items**；默认 10 会分 5 页（2.23 s → 0.88 s） |

### 2.3 响应结构与分页

```json
{
  "type": "FeatureCollection",
  "context": {"matched": 41, "returned": 41},
  "numberMatched": 41,
  "numberReturned": 41,
  "features": [ /* STAC Item */ ],
  "links": [{"rel": "next", "href": "...", "method": "POST"}, {"rel": "root"}]
}
```

`pystac-client` 的 `search().items()` 会顺着 `links[rel=next]` 翻页，直到 `max_items`。
现在 `limit = max_items`，一次拿完，不会产生 `next`。

### 2.4 缓存

`sha1(provider + kwargs)` → `data/index/search_cache.sqlite`，TTL 24 h（`RSPIPE_CACHE_TTL`）。
命中时反序列化 `pystac.Item.from_dict`，与线上路径完全一致；损坏则自动回退网络。

## 3. 逐源详解

### 3.1 earth-search（Sentinel-2 L2A）

**检索**：`POST /v1/search`，无任何头。

**响应 item 实测**：

```json
{
  "id": "S2C_49SFB_20261021_0_L2A",
  "collection": "sentinel-2-l2a",
  "bbox": [112.1232, 36.9345, 113.3869, 37.9421],
  "geometry": {"type": "Polygon"},
  "properties": {
    "datetime": "2026-10-21T03:27:36.119000Z",
    "platform": "sentinel-2c",
    "eo:cloud_cover": 10.864911,
    "proj:epsg": 32649
  },
  "assets": { /* 38 个 */ }
}
```

**资产 key**（38 个）：`aot blue cloud coastal green nir nir08 nir09 red rededge1 rededge2 rededge3 scl visual …`

```json
"blue": {
  "href": "https://sentinel-cogs.s3.us-west-2.amazonaws.com/sentinel-s2-l2a-cogs/49/S/FB/2026/10/S2C_.../B02.tif",
  "type": "image/tiff; application=geotiff; profile=cloud-optimized",
  "roles": ["data", "reflectance"]
}
```

- 公开 S3，**无 token、无签名**
- 取像素：`GET` + `Range: bytes=0-262143`
- 一景 5 波段 ≈ 1 次 POST + 5 个并发 Range

### 3.2 planetary-computer（Landsat C2 L2）

**检索**：`POST /api/stac/v1/search`，无鉴权。

**响应 item 实测**：

```json
{
  "id": "LC09_L2SP_125034_20261013_02_T1",
  "collection": "landsat-c2-l2",
  "bbox": [111.416, 36.3962, 114.0522, 38.5283],
  "properties": {
    "datetime": "2026-10-13T03:06:48.860872Z",
    "platform": "landsat-9",
    "eo:cloud_cover": 0.47,
    "landsat:collection_category": "T1",
    "proj:epsg": 32649,
    "gsd": 30
  },
  "assets": { /* 25 个 */ }
}
```

**资产 key**：`qa ang red blue drad emis emsd trad urad atran cdist green nir08 lwir11 qa_pixel rendered_preview …`

```json
"red":        {"href": "https://landsateuwest.blob.core.windows.net/landsat-c2/level-2/standard/oli-tirs/.../SR_B4.TIF", "roles": ["data","reflectance"]},
"qa_pixel":   {"roles": ["cloud","cloud-shadow","snow-ice","water-mask"]},
"rendered_preview": {"href": "https://planetarycomputer.microsoft.com/api/data/v1/item/preview.png?collection=...", "roles": ["overview"]}
```

**取像素前必须签名**（裸 Blob 直接 403）：

```bash
curl -s "https://planetarycomputer.microsoft.com/api/sas/v1/sign?href=<URL编码后的资产地址>"
```

```json
{
  "href": "https://landsateuwest.blob.core.windows.net/...?sv=...&se=2026-10-31T00:25:58Z&sig=E4P%2FDDc%2F2fuQ...",
  "msft:expiry": "2026-10-31T00:25:58Z"
}
```

- token 约 1 h；`signing.py` 提前 120 s 重签，同 href 合并请求，并发上限 4（`RSPIPE_SIGN_CONCURRENCY`），429 按 `Retry-After` 退避
- **签名是逐资产的**：一景 Landsat 6–10 个资产 → 一景 6–10 次签名（429 的主要来源）
- 签名后同样走 `Range` 请求

```json
  "collection": "landsat-c2l2-sr",
  "properties": {"platform": "LANDSAT_8", "eo:cloud_cover": 0.01, "landsat:collection_category": "T1", "proj:epsg": 32649},
  "assets": { /* 17 个 */ }
}
```

**资产 key**：`thumbnail reduced_resolution_browse index MTL.json coastal blue green red nir08 swir16 swir22 qa_aerosol qa_pixel qa_radsat …`

```json
"red": {"href": "https://landsatlook.usgs.gov/data/collection02/level-2/standard/oli-tirs/2026/125/034/.../SR_B4.TIF",
        "type": "image/vnd.stac.geotiff; cloud-optimized=true",
        "roles": ["data"]}
```

- `fetch_mode: download`（整景 tar）

### 3.4 cdse-s2（Copernicus Data Space）

**检索公开**（实测无 token 也是 200）：

```bash
curl -s -X POST https://catalogue.dataspace.copernicus.eu/stac/search \
  -H 'Content-Type: application/json' \
  -d '{"collections":["sentinel-2-l2a"],"bbox":[112.5,37.7,112.6,37.8],"datetime":"2026-09-01T00:00:00Z/2026-10-30T00:00:00Z","limit":1}'
```

**响应 item 实测**：

```json
{
  "id": "S2B_MSIL2A_20261026T031819_N0513_R118_T49SFB_20261026T070640",
  "assets": { /* 47 个 */ }
}
```

**资产 key**（按分辨率后缀）：`AOT_10m AOT_20m AOT_60m B01_20m B02_10m B02_20m B02_60m B03_10m …`

```json
"AOT_10m": {"href": "s3://eodata/Sentinel-2/MSI/L2A/2026/10/26/S2B_MSIL2A_.../AOT_10m.jp2",
            "roles": ["data", "gsd:10m"]}
```

- 资产是 **`s3://eodata/` 协议**，需要 CDSE 的 S3 凭证（在 CDSE 门户生成 Access Key），仅 Bearer token 不够
- 检索/下载的 OAuth2：

```http
POST https://identity.dataspace.copernicus.eu/auth/realms/CDSE/protocol/openid-connect/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id=...&client_secret=...
→ {"access_token":"...","expires_in":600}
```

- `auth.py:TokenProvider` 自动刷新（提前 30 s）
- 缺 `CDSE_CLIENT_ID/SECRET` → 启动即 `provider.skipped`，不影响其他源

## 4. 波段名对照（同一物理波段，三种叫法）

| 通用名 | earth-search | planetary-computer | usgs-landsat | cdse-s2 |
|---|---|---|---|---|
| blue | `blue` | `blue` | `blue` | `B02_10m` |
| green | `green` | `green` | `green` | `B03_10m` |
| red | `red` | `red` | `red` | `B04_10m` |
| nir | `nir` | `nir08` | `nir08` | `B08_10m` |
| swir1 | `swir16` | `swir16` | `swir16` | `B11_20m` |
| swir2 | `swir22` | `swir22` | `swir22` | `B12_20m` |
| 云掩膜 | `scl` | `qa_pixel` | `qa_pixel` | `SCL_20m` |

解析顺序（`bands.py`）：**资产 key 精确匹配 → `_COMMON_ALIASES` 别名 → `sensors.yaml` 的 `band_map`**。
所以同一套代码能吃四种命名，靠的就是这张别名表。

## 5. 资产获取：三种模式

`providers.yaml` 的 `fetch_mode`：

| 模式 | 行为 | 典型用途 |
|---|---|---|
| `vsi` | 不落盘，`RangeFile` 按需读 COG 窗口 | 预览、指数、AOI 裁剪 |
| `download` | 完整下载到 `data/raw/`，断点续传 | 整景归档、USGS/CDSE |
| `windowed` | 按 bbox 窗口裁剪后落盘 | 要文件但只要 AOI |

`RangeFile` 参数（环境变量可调）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `RSPIPE_MAX_CONNECTIONS` | 32 | 全局并发连接上限 |
| `RSPIPE_PREFETCH_BLOCKS` | 8 | 顺序读时预取后续块数 |
| 块大小 | 256 KiB | `DEFAULT_BLOCK` |
| 块缓存 | 512 块（128 MiB） | 单文件 LRU |

> 为什么强调并发：实测单连接被限速到 **14–17 KB/s**，32 并发约 **260 KB/s**、64 并发 343 KB/s。
> 预取 8 块时单文件读取从 17 KB/s 提到 100 KB/s。

## 6. 请求次数与耗时（一景 5 波段）

```
earth-search : 1×POST + 5×Range（并发）                 ≈ 1–2 s
PC           : 1×POST + 5×sign + 5×Range（并发）         ≈ 2–5 s
USGS         : 1×POST + 1×整景下载（数百 MB）             ≈ 分钟级
CDSE         : 1×POST（公开）+ 1×token + 1×整景下载        ≈ 分钟级
```

检索阶段只拿元数据（一条 item 3–8 KB），**不下载像素、不签名、不算 AOI 云量**；
签名发生在读 QA / 瓦片 / 下载时。

## 7. 常见错误对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `sign HTTP 429` | PC 签名限流 | 已限并发 4 + 退避；可调小 `RSPIPE_SIGN_CONCURRENCY` |
| 资产 403 且 URL 带 `sig=` | SAS 过期（约 1 h） | 已提前 120 s 重签；异常时可清 `search_cache.sqlite` 的 kv 表 |
| 检索 401 | CDSE token 缺失/过期 | 检查 `CDSE_CLIENT_ID/SECRET`，token 自动刷新 |
| 下载 302 到登录页 | USGS 未登录 | 配 `USGS_M2M_USERNAME/TOKEN` |
| `provider.skipped` | 该源缺凭证 | 正常降级，其他源不受影响 |
| 同条件二次检索 0.2 s | 缓存命中 | 正常 |
| 换 AOI 就变慢 | 缓存未命中（key 含 bbox/日期/云量） | 正常，冷检索 30–45 s |

## 8. 两个默认关闭的客户端

### 8.1 `usgs-m2m`（EarthExplorer JSON API，非 STAC）

```http
POST https://m2m.cr.usgs.gov/api/json/stable/search
X-Auth-Token: <USGS_M2M_TOKEN>

{"datasetName":"landsat_ot_c2_l2",
 "maxResults":50,
 "startingNumber":1,
 "sortOrder":"ASC",
 "spatialFilter":{"filterType":"mbr",
                  "lowerLeft":{"latitude":37.7,"longitude":112.5},
                  "upperRight":{"latitude":37.8,"longitude":112.6}},
 "temporalFilter":{"startDate":"2026-09-01","endDate":"2026-10-30"},
 "metadataFilter":{"filterType":"and","childFilters":[
   {"filterType":"between","fieldId":20514,"firstValue":"0","secondValue":"30"}]}}
```

- `fieldId 20514` 是 USGS 的「Cloud Cover」字段
- 需要 `pip install rspipe[m2m]`（`usgsxplore`）+ `.env` 里的账号/token

### 8.2 `cdse-odata`（OData，补充路径）

```http
GET https://catalogue.dataspace.copernicus.eu/odata/v1/Products
    ?$filter=Collection/Name eq 'SENTINEL-2'
      and OData.CSC.Intersects(area=geography'SRID=4326;POLYGON((...))')
      and ContentDate/Start gt 2026-09-01T00:00:00.000Z
    &$orderby=ContentDate/Start desc
    &$top=50
```

- 好处是能拿到 OData 独有字段（`ContentLength`、`Online`、`S3Path` 等）
- 与 STAC 路径并存，默认关闭

## 10. 新增数据源的最小步骤

1. `configs/providers.yaml` 加一段：`type: stac` + `url` + `collections` + `auth` + `fetch_mode`
2. 需要 OAuth2 就在 `.env` 补变量（参考 `CDSE_CLIENT_ID/SECRET`）
3. 资产在别的云上且要签名 → `ingest/signing.py` 的 `_PC_HOSTS` 加主机
4. 波段命名不通用 → `configs/sensors.yaml` 补 `band_map`，或在 `bands.py` 的 `_COMMON_ALIASES` 加别名
5. 验证：`rspipe search --provider <name>` → Web 页勾选该源 → 预览瓦片能出图
