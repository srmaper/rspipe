# 数据源接入说明（请求方法与鉴权）

> 面向：想换数据源、排查 401/403/429、或自己接新 provider 的人。
> 代码位置：`src/rspipe/clients/stac.py`（检索）、`ingest/signing.py`（SAS 签名）、
> `auth.py`（OAuth2/M2M）、`ingest/fetcher.py`（资产获取）、`configs/providers.yaml`（配置）。

## 1. 总览

| provider | 类型 | 检索端点 | 检索鉴权 | 资产 | fetch_mode | 默认启用 |
|---|---|---|---|---|---|---|
| `earth-search` | STAC | `https://earth-search.aws.element84.com/v1` | 无 | 公开 S3 COG | vsi | 是 |
| `planetary-computer` | STAC | `https://planetarycomputer.microsoft.com/api/stac/v1` | 无 | Azure Blob（需 SAS） | vsi | 是 |
| `usgs-landsat` | STAC | `https://landsatlook.usgs.gov/stac-server` | 无（下载需 EROS） | usgs.gov HTTPS | download | 是 |
| `cdse-s2` | STAC | `https://catalogue.dataspace.copernicus.eu/stac` | OAuth2 Bearer | CDSE HTTPS/S3 | download | 是 |
| `usgs-m2m` | M2M API | `https://m2m.cr.usgs.gov/api/json/stable/` | M2M token | 同上 | download | 否 |
| `cdse-odata` | OData | `https://catalogue.dataspace.copernicus.eu/odata/v1` | OAuth2 Bearer | 同上 | download | 否 |

前四个走同一套 `StacClient`（pystac-client），差异只在 **URL / collections / 鉴权头 / 资产获取方式**。

## 2. 统一检索：`POST {stac_url}/search`

```http
POST https://earth-search.aws.element84.com/v1/search
Content-Type: application/json

{
  "collections": ["sentinel-2-l2a"],
  "bbox": [112.5, 37.7, 112.6, 37.8],
  "datetime": "2026-09-01T00:00:00Z/2026-10-30T00:00:00Z",
  "limit": 50,
  "max_items": 50,
  "query": {"eo:cloud_cover": {"lte": 30}}
}
```

参数组装见 `stac.py:157`：

| 字段 | 何时带 | 说明 |
|---|---|---|
| `collections` | 总是 | 来自 `providers.yaml` 的 `collections` |
| `ids` | 按 id 反查（下载/详情） | 与 bbox 互斥，优先级最高 |
| `bbox` / `intersects` | 有 AOI 时 | 二选一，多边形走 `intersects` |
| `datetime` | 有起止日期时 | 统一 `YYYY-MM-DDTHH:MM:SSZ/...` |
| `query` | 云量上限 | `eo:cloud_cover: {lte: N}`，**服务端过滤** |
| `max_items` | 总是 | 上限 50 |
| `limit` | 总是 | **= max_items**，避免 pystac-client 按默认 10 条分页（5 次往返 → 1 次，2.23 s → 0.88 s） |

检索结果按 `sha1(provider + kwargs)` 落 `data/index/search_cache.sqlite`，TTL 24 h（`RSPIPE_CACHE_TTL`）。

## 3. 逐源详解

### 3.1 earth-search（Sentinel-2 L2A）

- 检索：`POST /v1/search`，无需任何头
- 资产：`https://sentinel-cogs.s3.us-west-2.amazonaws.com/sentinel-s2-l2a-cogs/{utm}/{lat}/{sq}/{yyyy}/{mm}/{scene}/{BAND}.tif`
- 取像素：直接 `Range: bytes=0-262143` 打 S3，**无 token**
- 一景 5 波段 ≈ 1 个 POST + 5 个并发 Range

### 3.2 planetary-computer（Landsat C2 L2）

- 检索：`POST /api/stac/v1/search`，无需任何头
- 资产：`https://landsateuwest.blob.core.windows.net/landsat-c2/level-2/standard/.../SR_B2.TIF`（**裸 Blob，无 `?sig=` 直接 403**）
- 取像素前必须逐个资产签名：

```http
GET https://planetarycomputer.microsoft.com/api/sas/v1/sign?href=<URL 编码后的资产地址>

200 {
  "href": "https://landsateuwest.blob.core.windows.net/...?sv=...&se=2026-10-31T00:25:58Z&sig=...",
  "msft:expiry": "2026-10-31T00:25:58Z"
}
```

- token 约 1 小时有效；`signing.py` 带过期缓存（提前 120 s 重签）、同 href 合并请求、并发上限 4（`RSPIPE_SIGN_CONCURRENCY`）、429 按 `Retry-After` 退避
- 一景 Landsat 有 6–10 个资产 → **一景要签 6–10 次**，这是 429 的主要来源

### 3.3 usgs-landsat（LandsatLook STAC）

- 检索：`POST /stac-server/search`，公开
- 资产：`https://landsatlook.usgs.gov/data/collection02/level-2/standard/oli-tirs/...`，`roles: ["data"]`
- **检索免费、下载要 USGS EROS 账号**（未登录会 302 到登录页）
- 配 `USGS_M2M_USERNAME` / `USGS_M2M_TOKEN` 后改用 M2M API 拿下载地址
- `fetch_mode: download`（整景 tar，不做窗口读）

### 3.4 cdse-s2（Copernicus Data Space）

- 检索：`POST https://catalogue.dataspace.copernicus.eu/stac/search`（落地页 `GET /stac` 公开 200）
- 鉴权：OAuth2 client_credentials

```http
POST https://identity.dataspace.copernicus.eu/auth/realms/CDSE/protocol/openid-connect/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id=...&client_secret=...
→ {"access_token": "...", "expires_in": 600}
```

- 之后检索与下载均带 `Authorization: Bearer <token>`，token 自动刷新（`auth.py:TokenProvider`）
- 缺 `CDSE_CLIENT_ID` / `CDSE_CLIENT_SECRET` 时启动即 `provider.skipped`，不阻塞其他源

## 4. 资产获取的三种模式

配置项 `fetch_mode`（`providers.yaml`）：

| 模式 | 行为 | 适用 |
|---|---|---|
| `vsi` | 不落盘，`RangeFile` 按需读 COG 窗口（默认） | 预览、指数、AOI 裁剪下载 |
| `download` | 完整下载到 `data/raw/`，断点续传 | 整景归档、USGS/CDSE |
| `windowed` | 按 bbox 窗口裁剪后落盘 | 只要 AOI 范围但要文件 |

`RangeFile` 的关键参数：块 256 KiB（默认）、顺序读预取 8 块（`RSPIPE_PREFETCH_BLOCKS`）、
全局并发上限 32（`RSPIPE_MAX_CONNECTIONS`）。单连接常被限速（实测 14–17 KB/s），
并发才是吞吐来源（32 并发约 260 KB/s）。

## 5. 请求次数与耗时（一景 5 波段）

```
earth-search : 1×POST + 5×Range（并发）              ≈ 1–2 s
PC           : 1×POST + 5×sign + 5×Range（并发）      ≈ 2–5 s
USGS         : 1×POST + 1×整景下载（数百 MB）          ≈ 分钟级
CDSE         : 1×token + 1×POST + 1×整景下载           ≈ 分钟级
```

检索本身只拿元数据 JSON（一条 item 约 3–8 KB），**不下载像素、不签名、不算 AOI 云量**；
签名发生在读 QA / 瓦片 / 下载阶段。

## 6. 常见错误对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `sign HTTP 429` | PC 签名限流（并发过高） | 已限并发 4 + 退避；必要时调小 `RSPIPE_SIGN_CONCURRENCY` |
| 资产 403 且 URL 带 `sig=` | SAS token 过期（约 1 h） | 已在 120 s 前自动重签；手动清缓存 `rspipe.cache` 的 kv 表 |
| 检索 401 | CDSE token 缺失/过期 | 检查 `CDSE_CLIENT_ID/SECRET`；token 自动刷新 |
| 下载 302 到登录页 | USGS 未登录 | 配 `USGS_M2M_USERNAME/TOKEN` |
| `provider.skipped` | 该源缺凭证 | 正常降级，其他源不受影响 |
| 检索很慢但结果一样 | 缓存未命中（换了 AOI/日期/云量） | 属正常；同一条件二次检索 <0.2 s |

## 7. 新增数据源的最小步骤

1. `configs/providers.yaml` 加一段（`type: stac` + `url` + `collections` + `auth` + `fetch_mode`）
2. 若是 OAuth2，在 `.env` 补 `CDSE_CLIENT_ID/SECRET` 一类变量
3. 资产需签名（非 PC 的云存储）→ 在 `ingest/signing.py` 的 `_PC_HOSTS` 加主机
4. 波段名与产品不一致 → 在 `configs/sensors.yaml` 补 `band_map`
5. `rspipe search --provider <name>` 验证检索，再在 Web 页勾选该源
